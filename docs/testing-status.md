## Fixes covered by regressions

- Update checking is exercised through its actual orchestration, not just feed-parsing helpers. Feed URLs clear search filters, request date ordering and avoid stale cache responses. Checkpoints use distinct recent-entry fingerprints rather than requiring an assumed timestamp field. Missing timestamps, early pinned entries, conflicting duplicates, repeated pages, catch-up limits, malformed/empty/error payloads and interrupted scans have regression coverage. Conflicting version duplicates trigger thread verification without trusting their timestamps to suppress a candidate.
- Changed linked IDs are checked through the existing authenticated thread reader without cover downloads; unlinked games are reported rather than guessed by title. Baseline and overdue verification are bounded by their purpose, while unchanged incremental checks avoid full-library thread requests. Explicit full checks recover large feed gaps; if the feed itself fails, successful direct thread results are retained while the checkpoint/error still reflects that failure.
- Successful thread results survive a partial failure, but the global checkpoint and last-completed time only advance after a complete check. Failed or lagging thread responses remain retryable. A newer numeric feed release paired with an older returned thread version keeps the check incomplete instead of marking the discrepancy processed. Version comparison covers older numeric releases, equal padded numeric versions, unknown installed releases, packed labels and nonnumeric chapter labels; creator names containing digits are not parsed as versions.
- Actual Chromium loopback requests now exercise the complete update pipeline: authenticated feed redirect, thread redirect, version verification, JSON persistence, unchanged subsequent polling and expired-login failure with the previous checkpoint preserved. The real renderer drives both incremental and forced-full controls through the checker. These fixtures do not prove live F95 feed ordering or compatibility; user-operated Check for updates and Check all linked threads remain necessary live checks.
- Opening-post extraction explicitly prioritizes the thread starter over earlier unrelated wrappers. Descriptions exclude scripts/styles/templates, quote blocks and forum controls, and prefer the Overview/Description section. Generated fixtures reproduce the user-reported lightbox JSON without inspecting live HTML.
